# 首轮输入对齐问题协议

## 总原则

- 首轮问题不是固定全部抛给用户，而是先从用户原话、上传资料、文件名、模板和申报指南中自动抽取。
- 能明确抽取的字段，写入 `answered_question_ids`，不重复询问。
- 抽取不到、存在歧义、或必须由用户明确授权的字段，写入 `pending_question_ids` 并询问用户。
- 多 Agent 降级确认必须单独成轮，不能和资料收集问题混在一起。
- 用户回答问题时通常不能同时补上传文件，因此需要文件或模板时，应结束当前回答，等待用户下一轮提供选择或文件。

## 第 0 轮：能力自测与降级确认

只有当当前 SDK 或运行环境不支持多 Agent 时，才进入本轮。

```text
当前运行环境不支持多 Agent 架构。
发挥完整性能需要使用支持多 Agent 的 SDK，完整功能可能消耗大量 token。

请只回复数字：
1. 接受降级，继续任务
2. 取消任务
```

规则：

- 用户回复 `1` 后，进入第 1 轮输入对齐。
- 用户回复 `2` 后，任务状态为 `CANCELLED_BY_USER`。
- 用户未回复 `1` 或 `2` 时，不得继续。
- 本轮不得同时询问标题、模板、字数、资料或格式问题。

## 第 1 轮：输入对齐字段

### A. 优先自动抽取，不足才问

| question_id | 字段 | 自动抽取来源 | 抽取不到时的问题 |
|---|---|---|---|
| `project_title` | 项目标题 | 用户原话、资料标题页、文件名、模板标题 | 项目标题是什么？ |
| `research_theme` | 研究主题/核心方向 | 项目标题、摘要、研究内容、关键词 | 研究主题或核心方向是什么？ |
| `reference_materials_status` | 参考资料状态 | 上传文件、粘贴材料、用户说明 | 你是否已经提供参考资料？如果没有，请说明后续会提供哪些资料。 |
| `content_template_source` | 内容模板/申报指南来源 | 用户上传模板、指南、Word/PDF/Markdown | 你是否提供了内容模板或申报指南？如果没有，我将使用内置六类模板之一。 |
| `template_family_selection` | 内置模板族 | 用户模板、申报类型、资料说明 | 请在六个内置模板族中选择一个。见下方双语说明。 |
| `funding_program` | 申报计划/资助类型/项目类别 | 申报指南、模板标题、用户描述 | 申报计划、资助类型或项目类别是什么？如果暂无，请回复“暂未确定”。 |
| `target_length` | 目标字数或页数 | 模板、申报指南、用户要求 | 目标字数或页数是多少？如果没有要求，请回复“按模板默认”。 |
| `output_formats` | 输出格式 | 用户要求，如“只要 Word” | 最终需要哪些格式？Markdown、JSON、DOCX？ |
| `docx_required` | 是否需要 DOCX/Word | 用户要求，如“Word”“docx”“最终 word” | 是否需要生成 DOCX/Word？请回复“需要”或“不需要”。 |
| `deadline_or_delivery_time` | 截止时间/期望交付时间 | 用户原话、任务说明 | 截止时间或期望交付时间是什么？如果暂无，请回复“暂无”。 |

`deadline_or_delivery_time` 是调度字段，不是正文事实字段。它只用于判断是否需要先出草稿、压缩审核节奏或标记交付优先级；抽取不到时默认 `暂无`，不得阻塞流程。

### B. 必须明确确认

| question_id | 字段 | 询问规则 |
|---|---|---|
| `web_search_permission` | 联网检索确认 | 正式参考文献必须联网检索和核验。请确认当前任务允许联网检索正式参考文献。 |
| `docx_format_template_source` | DOCX/Word 格式模板来源 | 你是否提供 DOCX/Word 格式模板？如果没有，我会先展示内置格式模板，征得你同意后才使用。 |
| `builtin_docx_format_approval` | 内置 DOCX 格式模板确认 | 仅当用户未提供 DOCX 格式模板时询问：你是否同意使用内置 DOCX 格式模板？ |
| `missing_info_policy` | 缺失信息处理策略 | 遇到缺失信息时，是先占位继续，还是停住等你补资料？ |

### C. 默认告知，不作为选择题

| 字段 | 默认规则 |
|---|---|
| `human_review_setting` | 人工审核默认启用；如需关闭，用户必须明确说明。 |
| `image_generation_policy` | 本流程不生成实际图片。若章节写作需要图示，将在对应位置输出图片生成提示词或 Mermaid 参考内容。 |
| `attachment_policy` | 团队简历、证明材料、预算表、合作协议、成果清单等附件只接收用户提供；用户没提供则留空。 |
| `table_policy` | 表格严格按用户模板和用户数据生成；没有模板或数据则留空或占位，不编造表格内容。 |

## 六个内置模板族双语说明

```text
1. 基础研究类 basic_research
   适用于自然科学基金、基础理论、机理研究、方法创新类申请。

2. 任务研发类 mission_rnd
   适用于重点研发、任务牵引、技术攻关、工程化验证类申请。

3. 社科研究类 social_science
   适用于哲学社会科学、政策研究、管理研究、调研报告类申请。

4. 产业研发类 industry_rnd
   适用于企业技术研发、产品开发、成果转化、产业化项目申请。

5. 平台建设类 platform_construction
   适用于实验室、基地、平台、条件建设、能力建设类申请。

6. 简版建议书 compact_proposal
   适用于预申报、短版项目建议书、通用简版申请材料。
```

模板族不明确时，必须让用户选择编号或英文 ID，不得自动替用户选择。

## DOCX 格式模板条件问题

当 `docx_required = true` 时，必须按以下顺序处理：

```text
用户给 DOCX 格式模板
  -> 严格抽取模板格式
  -> 按用户模板生成

用户没给 DOCX 格式模板
  -> 展示内置模板格式
  -> 问用户是否同意

用户同意
  -> 使用内置模板格式

用户不同意
  -> 问用户是否有模板提供

用户提供
  -> 回到“严格抽取模板格式”

用户不提供
  -> 逐项询问字体、字号、行距、页边距、标题、表格、图题、页眉页脚等
```

## 建议启动问题文本

总控代理向用户展示时，应只包含未回答或必须确认的问题：

```text
我会先从你提供的资料中自动抽取已明确的信息，不重复询问。
以下是仍需你确认的内容：

1. [缺失字段问题]
2. [缺失字段问题]
...
```

若模板族需要用户选择，使用双语选项，不使用纯英文枚举。
